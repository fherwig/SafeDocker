# Safe 0.3.2

The first public release of Safe.app.

## What Safe is

Safe is a Mac app that keeps files encrypted and lets you use them from the Finder.
"Encrypt with Safe" in a file's right-click menu turns `report.pdf` into
`report.pdf.crypt` and deletes the original after checking the encrypted copy. A
double-click on a `.crypt` file opens text in a small editor, and PDFs and pictures in a
viewer. The decrypted content stays in the app's memory and is never written to the disk.
Safe also makes and opens encrypted volumes (AES-256 sparse bundles, Apple's own disk
images), empty or from a folder. It has no network access, locks after 10 minutes without
input and when the Mac sleeps, and speaks English and German.

The files are in openssl's format (AES-256-CBC, PBKDF2 with SHA-512, 100,000 iterations).
They open without Safe, with macOS's own `openssl` or with `tools/safe-decrypt.py`, which
needs nothing but Python 3.

Safe needs macOS 13 or later, on Apple silicon or Intel. Nothing else.

## Install

Three ways, in order of ease. All three put Safe into the Applications folder of your home
folder and never ask for an administrator's password.

1. **The installer.** Download `Safe.pkg` (the same file as `Safe-0.3.2.pkg`) below and
   open it. Then start Safe once from your Applications folder, so that the Finder learns
   its right-click menu items.
2. **The Terminal.** Paste this line into the Terminal:

       curl -fsSL https://raw.githubusercontent.com/fherwig/Safe/main/install-safe.sh | bash

   It downloads `Safe.zip`, checks its SHA-256 checksum against `SHA256SUMS`, checks the
   app's signature and self-test, installs it and starts it once.
3. **An AI agent.** Ask an AI system administration agent (Claude Code, Codex and the like)
   to install Safe by following
   [INSTALL-AGENT.md](https://github.com/fherwig/Safe/blob/main/INSTALL-AGENT.md). It never
   sees your passwords and never touches your encrypted files.

You can also build Safe yourself with Apple's Command Line Tools:
`bash install-safe.sh --from-source` in a clone of the repository.

## The app is not signed by Apple

Safe has no Developer ID and is not notarised: it is signed ad hoc. So macOS refuses to
open the installer the first time and says that Apple could not check it. On macOS 15
(Sequoia) and later, click Done, open System Settings > Privacy & Security, scroll down to the
line that says Safe.pkg was blocked, click Open Anyway and confirm with your password. On macOS 13 and
14, right-click the installer, choose Open and confirm. If macOS then also refuses Safe
itself, allow it the same way. The Terminal install does not meet this question, because
curl, unlike a browser, does not mark its downloads as coming from the internet; the
checksum and the signature check take that place.

## What is new

Everything, since this is the first release:

- Encrypt files from the Finder; open, edit and save encrypted text with a `.bak` of the
  previous version; view encrypted PDFs and pictures; export a plain copy where you choose.
- Encrypted volumes: new empty, new from a folder (the folder is deleted after the check),
  open, close, change the password, add an existing one.
- Locking after 10 minutes without input on the Mac, and on sleep and screen lock.
- No network access, and a self-test at every start over reference files made by OpenSSL 3,
  LibreSSL, `crypt.sh` and Safe itself.
- Older files of `crypt.sh` (older AES and RC4 variants) open, and damaged files can be
  exported in part.
- Help in English and German (Help > Safe Help), tooltips, keyboard shortcuts, and a
  Settings window to choose the language; the shortcuts work on a German keyboard too.
- The licence (GPL-3.0-or-later) in the app, its help and Safe > About Safe.
- An installer, `install-safe.sh` and `INSTALL-AGENT.md`.

## Known gaps

- The 10 minutes count input anywhere on the Mac, not only in Safe.
- If Safe cannot switch off its network access, it does not start.
- A few rare cases are left to `tools/safe-decrypt.py`: an old AES file of a type Safe
  cannot check whose reading ties with the current format, and damaged files in the older
  AES variants.
- The Finder integration, the lock on a real sleep and some viewer details are checked by
  hand (`docs/safe-app/acceptance.md`), not by the automatic tests.

`docs/safe-app/architecture.md` (section 10) has the details.
